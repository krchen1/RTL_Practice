# RTL Practice Set

A set of 25 classic RTL interview/practice questions. Each question lives in
its own folder `qN/` with two files:

- `qN.sv` — the file **you edit**. It contains a header comment with the full
  problem statement, the module interface (already declared for you), and a
  `// TODO` where your implementation goes.
- `qN_tb.sv` — a self-checking testbench. **Do not edit this file.** Run it
  against your implementation; it prints exactly one of:
  - `TEST PASSED`
  - `TEST FAILED: <n> error(s)`

Every testbench was verified against a correct reference implementation (and,
for sequential designs, against a deliberately broken one) before being
committed to this set, so a clean implementation of the spec in the header
will pass.

You can run these two ways:

1. **Locally on the school Linux server**, using the Questa flow below (this
   repo already includes a `Makefile` for it).
2. **On an external site** (e.g. EDA Playground): copy the contents of
   `qN.sv` and `qN_tb.sv` into the site's editor as two separate files, pick a
   SystemVerilog-capable simulator (Questa, VCS, or the free Aldec/Icarus
   options all work — none of these testbenches use anything simulator
   specific), and run.

## Running locally with Questa

This machine/server has Questa available as an environment module. One-time
per shell session:

```sh
source /etc/profile      # only needed if `module` isn't already defined
module load questa       # loads the default Questa version
```

Then, from the `RTL_Practice/` root:

```sh
make test Q=q1           # compile + simulate question 1, prints TEST PASSED/FAILED
make test-all            # run all 25 questions, prints a PASS/FAIL summary table
make gui Q=q1            # same as `test` but opens the Questa waveform GUI
make clean               # remove all generated work/ and transcript files
```

`make test`/`make gui` just do the standard three-step Questa flow under the
hood, per question folder:

```sh
vlib work
vlog -sv qN.sv qN_tb.sv
vsim -c -do "run -all; quit -f" qN_tb    # drop -c and the -do for the GUI
```

If your server has multiple Questa versions and `module load questa` doesn't
pick the one you want, run `module avail questa` to see the list and edit
`QUESTA_MOD` at the top of the `Makefile` (e.g. to `questa/2024.2`).

## Global conventions used by every testbench

Keeping these consistent across all 25 questions is what makes a shared
Makefile and a shared testbench style possible:

- **Clock**: signal name `clk`, free-running, 10 ns period, driven by the
  testbench (`always #5 clk = ~clk;`).
- **Reset**: signal name `rst`, **synchronous, active-high**. The testbench
  asserts it for the first few cycles after time 0 and deasserts it before
  applying stimulus.
- Multi-bit signals are declared `logic [N-1:0]`, not `reg`/`wire`.
- Every testbench has an internal watchdog timeout, so a broken/hanging
  implementation still ends with `TEST FAILED` instead of running forever.
- Where a question is genuinely open-ended (e.g. the ROB, the LRU tracker,
  the pipeline datapath components), the header comment in `qN.sv` pins down
  one concrete, testable interface and behavior. Follow that spec exactly —
  the testbench checks against it, not against "any reasonable design."
